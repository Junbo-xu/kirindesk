## 结论

内部用户可以从有客户的草稿或锁定报价幂等创建销售订单，不依赖客户追踪链接确认。转换在一个租户事务中冻结报价版本和完整内部快照，创建订单与来源行项，补写报价到订单的关联，并追加两条 hash-chain 审计记录。普通订单 API、Web 与审计投影不返回成本、内部费用或完整内部快照。

## 验收与实现证据

| 验收项 | 实现 |
| --- | --- |
| 无需客户确认即可建单 | `POST /api/document-sets/:id/sales-order` 只要求可见报价、客户关联、`orders:create` 和当前版本，不读取匿名确认状态。 |
| 幂等创建 | 请求携带稳定幂等键；数据库同时唯一约束 `(tenant_id, source_document_set_id)` 与 `(tenant_id, source_quote_idempotency_key)`；相同请求返回原订单且不重复审计。 |
| 历史快照 | 订单冻结来源报价 ID、报价号、版本、完整内部 JSON 快照、转换人和时间；订单行冻结来源报价行快照与产品关联。数据库触发器禁止修改订单来源快照。 |
| 双向关联 | 报价返回 `sales_order_id`；订单返回 `source_document_set_id`、`source_quote_number` 和 `source_quote_version`。Web 报价工作台可转单并打开订单，订单列表和详情可回到指定报价。 |
| 锁定报价 | 锁定正文仍不可修改；数据库只允许一次性补写 `sales_order_id`。已保存的 `locked_snapshot` 不被改写，API 读取时叠加关系字段。 |
| 金额精度 | 订单头金额取冻结报价的精确 `grand_total`，行金额取冻结行快照，均以 PostgreSQL `numeric` 字符串传递，不经过 JavaScript 浮点计算。 |
| 隔离与财务安全 | 报价查询把 `orders:create` 与 `document_sets:view` scope 取保守交集；客户引用另按原始 `orders:create` scope 复用普通建单校验。跨租户、报价 owner 越界、报价可见但客户 owner 越界均统一 404。订单响应和审计白名单不包含来源内部快照、成本价、内部费用或毛利。 |
| 原子审计 | 订单、行项、双向关联和 `sales_order.created_from_quote` / `trade_document.converted_to_sales_order` 审计在同一事务；故障注入证明审计失败时业务写入全部回滚。 |

- 扩展 `sales_order_items` 的来源报价行、行快照和产品关联列。

- 新增来源快照不可变触发器，并收窄锁定报价的一次性关系补写例外。

## KIR-34 退回整改

Kai 首次复审发现报价转单只用 scope 交集校验报价，没有按 `orders:create` 原始 scope 再校验客户，导致“报价归调用者、客户归另一用户”的混合 scope 路径可以越权建单。

- 将普通销售订单创建的客户 scope 校验提取为共享函数，普通建单和报价转单使用相同的 `all` / `own` / `assigned` 语义与统一 404。
- 报价转单在读取并锁定报价后、任何订单、行项、报价回链或转换审计写入前，使用原始 `orders:create` actor 校验客户；幂等重试路径同样受校验。
- 新增混合 scope 回归：报价已归销售用户且 GET 可见，客户仍归管理员；转换返回 `404 Customer not found`，并验证 `sales_orders=0`、`trade_document_sets.sales_order_id=NULL`、两类转换审计合计 `0`。
- 整改复验：专项 `17/17`、全量集成 `433/433`、API/Web typecheck、目标 ESLint `0 error`；054/053 DOWN-UP 同 checksum，051 历史前向升级与自定义授权保留通过。

## 风险与未完成项

- 当前销售订单币种仍受既有 `RMB/USD/HKD/EUR` 约束；其他报价币种会以 `ORDER_CURRENCY_UNSUPPORTED` 明确阻断，不会静默换币。
- 订单头使用报价 `grand_total`，订单行保留商品行金额；折扣、运费、保险和税费的结构化订单字段属于 B 阶段订单驱动单证模型，当前由不可变来源快照保存，不宣称已可逐项编辑。
- 当前订单仍沿用既有草稿/审批状态；“订单锁定”及锁定后 PI/SC/CI/PL 刷新策略属于 B 阶段，未实现。
- 未开始供应商映射、采购拆单、发货批次、签收、附件、报关资料或报关 PDF。

## 回滚

首选应用回滚：部署上一版 API/Web并保留 054 结构与业务数据，转单入口不可见但历史订单和报价关系仍在。

数据库 DOWN 会删除订单和行项上的来源快照/幂等元数据，但不会删除已创建的订单，也不会清空 `trade_document_sets.sales_order_id`。这会丢失 A 阶段来源证据，因此仅允许在隔离环境或完成备份并经负责人批准后执行。DOWN 已纳入 `kirindesk_test` 往返演练；生产数据存在时优先前滚修复。
