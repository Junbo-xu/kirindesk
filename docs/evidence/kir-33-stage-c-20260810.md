# KIR-33 C 阶段交付证据：装箱驱动发货、在途与签收

## 范围与结论

本阶段在 A/B 已实现的销售订单来源快照、订单单证和采购审批之上，交付箱级履约闭环：锁定订单的 PL 箱级数据驱动发货批次，支持部分发货，状态依次为 `draft → dispatched → in_transit → delivered`，并记录签收人、签收时间、异常备注、附件和审计事件。

阶段 D 报关预录单、报关委托书、PDF 归档和 Files 归档尚未启动，不在本阶段完成声明内。

## 验收与实现证据

| 验收项 | 实现与证据 |
| --- | --- |
| PL 箱级数据驱动 | `FulfillmentService.packingListSourceDetails` 从当前订单 PL 版本读取箱号、订单行、数量、单件重量和体积，按 `normal/combined` 装箱模式构建箱清单；履约工作台通过 `packing_list_source.packages` 展示并选择箱号。 |
| 箱号、数量、毛净重、体积校验 | 创建发货批次前拒绝重复箱号、毛重小于净重、PL 外箱号、箱内订单行不匹配、数量超过 PL、按 PL 行精确计算不一致的净重或体积；错误码分别为 `DUPLICATE_PACKAGE_NUMBER`、`PACKAGE_WEIGHT_INVALID`、`PACKAGE_NOT_IN_PACKING_LIST`、`PACKAGE_ITEM_MISMATCH`、`PACKAGE_QUANTITY_EXCEEDED`、`PACKAGE_NET_WEIGHT_MISMATCH`、`PACKAGE_VOLUME_MISMATCH`。 |
| 部分发货 | 发货数量受已发数量和锁定订单可发数量共同约束；阶段 C 集成与浏览器用例以 PL 中 3 件的箱只发 1 件，最终断言已发/已签收 1 件、可发 2 件，订单聚合状态为 `fulfillment`。 |
| 状态与审计 | 发货、在途、签收均为明确状态迁移；`shipment.dispatched`、`shipment.in_transit`、`shipment.delivered`、物流事件审计和工作台业务事件在同一事务写入。重复在途事件按稳定幂等键回放原事件。 |
| 签收资料 | 签收强制 ISO 时间、非空签收人和至少一个 Files scope 内附件；第一附件作为凭证，其余可标记异常证据；签收备注和异常备注持久化并回显。 |
| 幂等与隔离 | 发货创建持久化 `idempotency_key/creation_request`，同 key 同 payload 回放、异 payload 返回 409；物流事件同样持久化幂等请求；租户 RLS、文件 scope、订单 owner scope 和跨租户 404 回归通过。 |

## 代码与迁移

- API：`apps/api/src/fulfillment/fulfillment.service.ts` 的 PL 源解析、箱级校验、发货幂等、在途状态、签收附件和审计事务；`fulfillment.controller.ts` 暴露履约路由，DTO 限制重量、体积、数量、附件和幂等键格式。
- Web：`apps/web/src/fulfillment/FulfillmentPage.tsx` 从 PL 箱选择并预填箱行，支持单行/多行箱数量编辑、箱级重量体积、在途和签收信息；`apps/web/src/lib/types.ts` 和 `api-client.ts` 对齐 API 投影。
- 数据库：`db/migrations/056_packing_driven_shipments.sql` 扩展 `shipments/logistics_events` 的幂等、PL 版本和状态字段，新增 append-only 的 `shipment_boxes`、`shipment_box_items`、`shipment_delivery_files`，启用并强制租户 RLS、复合外键、唯一约束和状态约束。
- 回滚：056 DOWN 先把 `in_transit` 映射为既有 `dispatched`，再删除箱/附件表、幂等和在途/PL 字段，恢复旧三态约束；执行后会丢失 C 阶段箱快照、签收附加附件和幂等历史，必须先备份并经负责人批准。优先应用回滚或前滚修复，不在生产执行本次开发工作区命令。

## 风险与边界

- 本阶段使用产品重量/体积作为 PL 的净重/体积基准，毛重由操作员录入并强制不小于净重；供应商、采购价和财务字段不进入发货/审计公开投影。
- 箱号在同一发货批次内唯一；同一 PL 箱可按部分数量分批发运，但业务上应由操作员保证实际外箱号与物流单据一致。
- 报关资料、HS/申报要素、口岸和委托方信息、报关 PDF 与 Files 归档属于阶段 D，未伪装为已完成能力。
- 本阶段没有生产数据库、生产凭据、客户数据、main 推送或生产发布。
