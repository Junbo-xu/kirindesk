# KIR-33 B 阶段交付证据：订单单证与采购拆单

## 范围与验收

本阶段只交付 B：销售订单驱动 PI、SC、CI、PL，以及按产品采购映射拆分采购单。未进入装箱发货、签收或报关。

验收口径：

- 销售订单可幂等生成或刷新一套订单单证；PI、SC、CI、PL 共享同一版本化数据源。
- 已导出 PDF 永不被刷新覆盖；刷新只创建新的单证源版本，并报告保留的历史导出数量。
- 销售订单可锁定履约快照；锁定后订单头与行项不可修改，后续单证使用锁定快照。
- 产品可配置默认供应商、采购币种和采购单价；财务投影与审计不泄露这些字段。
- 锁定订单可按供应商和采购币种自动拆成一张或多张采购单；缺少产品、供应商、采购币种或采购价时整笔阻断并返回逐行清单。
- 单证同步和采购生成都使用持久化 idempotency key；跨订单复用 key 返回冲突。
- 直生成采购单保持既有采购审批状态机，订单、映射、金额和来源快照不可静默改写。

## 实现证据

### API

- `POST /api/sales-orders/:id/fulfillment-lock`：使用 `expected_updated_at` 乐观锁，幂等写入完整订单履约快照。
- `POST /api/sales-orders/:id/document-set`：使用 `idempotency_key` 和订单版本生成/刷新订单单证；返回 PI、SC、CI、PL、源版本及历史导出保留数。
- `POST /api/sales-orders/:id/purchase-orders/generate`：只接受履约已锁定订单；完整校验所有行后，按供应商与采购币种拆单，整笔事务写入采购单、行项、订单关联和审计。
- 普通销售订单行项新增 `product_id`，使非报价来源订单也可进入同一真实链路。

### 数据与安全

- `055_order_documents_and_procurement.sql` 新增产品采购映射、销售订单履约锁定快照、订单单证同步历史、采购生成快照与直生成采购单来源字段。
- KIR-38 整改后，订单单证同步历史额外固定首次成功的内部单证快照、刷新标志和历史导出计数；旧 key 回放从该不可变记录重建结果，不再把历史版本号与当前单证正文拼接。
- 新表启用并强制租户 RLS；跨表关系使用 `(tenant_id, id)` 组合外键。
- 数据库触发器阻止履约锁定订单及行项变更，也阻止直生成采购单事实与行项变更；只允许既有采购审批的合法状态迁移。
- 产品采购映射仅随 `document_financials:view` 对应 scope 返回；产品与采购生成审计不写入采购单价、成本或供应商映射快照。
- 订单单证同步将 `document_sets:manage` scope 与 `orders:view` scope 取交集；采购生成将 `procurement:create` scope 与 `orders:view` scope 取交集。

### Web

- 产品库支持选择默认供应商、采购币种和采购单价，并在有财务权限时显示映射。
- 销售订单行项支持关联产品。
- 销售订单页提供“锁定履约快照”“生成/刷新 PI、SC、CI、PL”“按供应商生成采购单”；缺失映射清单按行展示，锁定后禁止保存订单事实。

## 迁移影响与回滚

- 首选应用回滚：部署上一版 API/Web，保留 055 加法结构和业务数据。
- 数据库回滚：055 DOWN 删除直生成销售订单↔采购单关联及同步/生成溯源表，移除采购映射与锁定字段；已生成采购单和行项保留为普通采购单，历史单证和 PDF 导出保留，但会失去本阶段来源关联与锁定语义。
- 因回滚会丢失来源关系和幂等历史，只能在备份完成、影响清单已核对并由负责人批准后执行。
- 本阶段没有生产数据迁移、生产凭据、分支推送、PR、`main` 合并或生产发布。

## 风险与后续边界

- 当前每个产品只有一套默认采购映射；多供应商比价和优先级不是 B 阶段范围。
- 同一供应商使用不同采购币种时会拆成不同采购单，避免混币金额。
- 订单履约锁定后仍允许既有审批状态迁移，但客户、币种、金额、行项和来源事实保持不可变。
- C 阶段需在此锁定订单、订单单证和采购关联之上实现箱级装箱、部分发货、在途与签收；本证据不声明 C 或 D 已完成。
