# KIR-45 Stage D 交付证据：报关资料、版本归档与审计

## 范围与结论

本阶段在 KIR-33 A/B/C 的锁定订单、CI/PL 快照、Files、Audit、RLS 与 RBAC 基础上，交付报关资料纵向闭环：已审批且已锁定销售订单 → 同版本 CI/PL 历史导出 → 一致性校验 → 报关草稿 → 两份真实 PDF → Files 归档 → 不可变版本 → 幂等导出与审计。

未接入生产海关、单一窗口或报关行接口；本阶段不声称具备真实电子申报能力，也未发布生产。

## 验收与实现证据

| 验收项 | 实现与证据 |
| --- | --- |
| 锁定来源 | 创建/刷新只选择当前租户、目标订单、已锁定单证集、`is_draft=false` 的最新 CI/PL 导出，并强制两者属于同一 `document_set_id/source_version`；订单必须已有履约锁定快照且处于已审批后的业务状态。 |
| 报关字段 | 归档数据包含 HS、申报要素、数量、单位、单价、金额、币种、包装、毛净重、口岸、贸易方式、委托方/报关行名称、统一社会信用代码、联系人、电话与授权事项。 |
| 一致性阻断 | API 对订单/CI/PL 的订单关联、锁定状态、币种、总额、行数、产品、数量、单位、单价、行金额、包装和重量做逐项校验；返回 `CUSTOMS_SOURCE_INCONSISTENT` 及结构化 `missing/conflicts`，不会写入半成品。 |
| 版本不覆盖 | `customs_declaration_versions` 与操作记录由数据库触发器保护为 append-only；刷新将当前集合恢复为 `draft` 并递增 `draft_revision`，但保留全部历史版本、来源指纹与 Files 引用。 |
| 真实 PDF/Files | `PuppeteerCustomsPdfRenderer` 分别生成报关单预录单样单、报关委托书；服务端校验 `%PDF-`，在同一业务事务写 Files 元数据、版本和 Audit，失败时清理对象存储。 |
| 幂等 | 创建、刷新、生成和导出持久化 `idempotency_key/request_hash/result_json`；同 key 同请求回放原集合/版本/文件，异请求返回 409。生成与导出在集合行锁下串行，避免并发重复版本。 |
| 安全 | 三张新表均 `ENABLE/FORCE RLS`，所有外键使用 `(tenant_id,id)`；控制器分别要求 `customs_declarations:view/manage/export` 并沿用 data scope。`none` scope 显式 fail-closed。报关 PDF 对通用 Files 列表、详情、删除和令牌接口不可见，只能由校验报关集合 owner scope 的 `customs_declarations:export` 领域接口签发一次性令牌，因此生成者与订单 owner 不同也不影响合法下载，宽 Files 权限也不能绕过报关权限。API/Audit 不返回锁定订单快照中的成本和内部利润字段。 |
| 审计 | 创建、刷新、生成、导出及两份系统生成文件均写入哈希链 Audit；集成测试验证链完整。 |

## API 与 Web

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/api/customs-declarations` | `customs_declarations:view` | 按报关 data scope 返回可查看集合，供最小权限 Web 页面选择，不依赖 `orders:view` |
| `GET` | `/api/sales-orders/:id/customs-declaration` | `customs_declarations:view` | 读取当前草稿和全部归档版本的安全投影 |
| `POST` | `/api/sales-orders/:id/customs-declarations` | `customs_declarations:manage` | 从锁定订单和最新 CI/PL 创建 |
| `POST` | `/api/customs-declarations/:id/refresh` | `customs_declarations:manage` | 刷新当前来源/委托信息，保留历史版本 |
| `POST` | `/api/customs-declarations/:id/generate` | `customs_declarations:manage` | 生成两份 PDF 并归档新版本 |
| `POST` | `/api/customs-declarations/:id/versions/:version/export` | `customs_declarations:export` | 幂等记录固定版本导出并返回 Files 引用 |
| `POST` | `/api/customs-declarations/:id/versions/:version/files/:documentType/token` | `customs_declarations:export` | 校验租户、报关 owner scope、固定版本和文件类型后签发一次性下载令牌 |

Web `/customs` 只向拥有 `customs_declarations:view` 的用户显示。页面先读取报关清单；只有同时具备 `customs_declarations:manage` 与 `orders:view` 才查询锁定订单并提供新建候选。`manage` 控制创建、刷新和生成，`export` 控制导出记录与两类下载；view-only 用户可读取已授权归档且页面初始化不会产生订单 403。前端在网络不确定时保留同一幂等键；异步订单加载使用序列号，旧请求不会覆盖用户新输入。

## 独立复审退回整改

- 可复现交付：Stage A–D 累积改动提交到 `feat/kir-33-fulfillment-loop` 并推送远端；复审材料以远端提交为准，不再依赖未提交工作树。
- 最小权限 Web：新增报关集合投影并按 `view/manage/export/orders:view` 分别门禁数据源和操作，Chromium view-only 场景验证无订单 API 请求、无修改/导出/下载按钮。
- 文件授权：报关 PDF 从通用 Files 浏览/令牌路径隔离，下载改走报关版本领域令牌；集成回归同时覆盖合法 owner 下载和宽 Files 权限绕过失败。
- fail-closed：`getBySalesOrder`、报关清单与通用 Files 查询均对未知或 `none` scope 追加 `false` 条件，避免异常历史授权退化为租户全量读取。

## 迁移与回滚

- 迁移：`057_customs_declarations.sql` 新增集合、不可变版本和幂等操作表，RLS、复合外键、权限映射、追加式触发器与受限 app role grants；`fulfillment_locked_snapshot` 新生成内容增加 `hs_code`，不修改既有锁定快照。
- 首选应用回滚：部署上一版 API/Web并保留 057 数据结构，使历史报关版本和 Files 引用仍可恢复读取。
- 数据库回滚：057 DOWN 会删除全部报关集合、版本、操作历史和三个报关权限；Files 行/对象不会自动删除。只允许在完成 `customs_declaration_versions` 与 `files.storage_key` 备份清单、负责人批准数据处置后执行。
- 前滚恢复：生成事务失败会删除本次已写对象并回滚 Files/版本/配额；若进程在对象写入与事务回滚间被强制终止，需按无 Files 行引用的 storage key 做受控孤儿清理。

## 风险与边界

- 报关 PDF 是可审核样单和委托书，不是海关电子申报报文；真实供应商接入必须另立项并补签名、回执、失败重试和对账。
- 申报要素来自锁定订单产品自定义字段 `declaration_elements`；既有锁定快照不含新加入的 `hs_code` 时会明确阻断，不能静默读取当前产品值覆盖历史。
- 毛重由经办人录入，服务端强制不小于 PL 净重；净重、箱数和包装行来自不可变 PL 导出。
- Chromium 每份文档独立启动浏览器，优先保证隔离；高并发渲染池或队列不在本阶段范围。
- 本阶段未使用生产凭据、客户数据、生产环境或 main 直推，仍需 Kai 独立复审后才能关闭 KIR-45/KIR-33。
